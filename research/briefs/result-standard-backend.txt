Owner (2026-10-26) wrote a standard for backtest results so runs are easy to track and compare. Every earlier run was deleted as unreliable (hat_backtest_run and HAT_DATA_ROOT/backtests/run_id=* are empty). The format and the code belong in the repo; the run data never does.

Do:
1. Put the spec in the repo as docs/backtests/result-standard.md, with run.schema.json and example_run.json beside it, and apply these orchestrator changes to it (mark them "v1.1 changes" at the end of the spec, bump format_version to "1.1" in schema and example):
   a. `strategy_version` is the full strategy version id; `engine_commit` the repo HEAD, with `-dirty` when the tree has changes.
   b. Run folders live at HAT_DATA_ROOT/backtests/runs/<run_id>/ (full run id). This replaces `backtests/run_id=<id>/report.json` and `trades.parquet`; remove that old format and its readers rather than keeping two. Nothing under HAT_DATA_ROOT is committed.
   c. Stock attributes are point-in-time or null, never today's values. Check what point-in-time data exists (market cap / shares outstanding, index memberships beyond NIFTY 500). Where it doesn't exist, the field is null and the breakdown is empty, and the spec says so. `adv_20d_cr` and the liquidity bucket (quintile of 20-day average traded value within that day's point-in-time universe) are always filled.
   d. `dsr_n_trials`: the number of distinct `resolved_hash` values among completed in-sample runs of the same strategy (same hash = duplicate, not a new trial). Keep it in a small registry the writer updates (a file under HAT_DATA_ROOT/backtests/, or the DB if that fits better); the DSR uses this count.
   e. Refusal reasons are exactly the spec's fixed codes. Split today's `max_positions` refusal into `max_positions` (the policy's max_open_positions) and `ladder_level` (the current exposure-ladder level's cap, below the policy cap). Map every existing gate to a code; an unmapped reason fails the run loudly.
   f. `fwd_r_20d`, `fwd_r_60d` (refusals) defined: from the would-be entry at the would-be stop, R at the close 20 / 60 sessions later, or −1 if a daily low reaches the stop first; null if the data ends first. Same no-lookahead rules as the engine; costs excluded and the column name says so if needed.
   g. Variants file items gain `base` (a label in the same file or a run id), `change` (one line) and the file gains `sweep_id` / `sweep_name`; CLI flags for single runs. `binding` is computed against `base` (trade_list_hash over symbol, entry_date, exit_date).
