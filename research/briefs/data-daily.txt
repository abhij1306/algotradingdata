Scheduled daily data update: one command, run after market hours by a timer, with catch-up for missed days, and easy to run by hand (agent or human). Branch hat/data-daily.
Owner 2026-10-29: "there should be a scheduled run for all other data updates which are required daily so we don't depend on manual updates; it can be scheduled post market hours or, if missed, run manually easily by agents or humans."
Context: the app's own nightly chain (docs/architecture.md "Nightly", daily/assembly.py:daily_jobs: ingest.nightly -> quality.gate, ca.adjust -> features ..., NIFTY 500 TRI) runs only inside the live service, which is not running on this box (HAT_ENABLED=false for research). Data updates have been run by hand (runbook.md). The box is an instabox VM that suspends after ~30 idle minutes and can be stopped (~/MACHINE.md): a missed run must catch up on the next start, never skip days.
Scope:
1. One entry point, e.g. `python -m app.hat.data.update [--through D] [--only STEP ...] [--dry-run]`, plus a one-line wrapper in scripts/. It runs every daily data step in dependency order, reusing the existing code paths (no second implementation):
   daily bhavcopy bars + index_daily/breadth + NIFTY 500 TRI (ingest/index_history nightly-tri), quality gate, corporate actions (ca.adjust: bc file, dividends, demergers, rescale), features_daily, index membership (nifty500_membership + load-index-membership, which notices take effect when), 5m bars top-up from Kotak for the last missing sessions + bars5m_import (scripts/data/kotak_5m.py; market data only, ~1 call/s, credentials from the env, never printed), NSE results filings incremental + derive + fundamentals extract/derive (weekly is fine if daily is wasteful; decide and say why), the ETF overlay store (overlay_etf.py) top-up.
   Catch-up: each step works out its own last stored day and fills every missing session through --through (default: the latest finished session), idempotent, resumable. A step that fails does not stop independent steps; dependents are skipped and reported.
2. Status: one machine-readable status file under HAT_DATA_ROOT (per step: last good session, last run, result, log path) and `--status` to print it; a non-zero exit when any step failed. Logs under HAT_DATA_ROOT/logs/update/<date>/. A lock so two runs never overlap (respect the minute-history lock).
3. Schedule: a systemd timer (or cron if systemd user timers are unavailable here; check) on trading days after market close, 19:30 IST, with Persistent=true / run-on-start catch-up so a suspended or stopped box runs the missed update when it next comes up. Install it on this box and show `systemctl list-timers` output. Runs against hat_live through the data-update paths only (the one writer allowed); never touches backtest runs.
4. Docs: runbook.md "Daily data update" section (what runs, the schedule, how to run by hand or one step, how to read status, how to recover), architecture.md one line. Compact.
5. Tests: pure functions only (step ordering/dependency skipping, missing-session computation, status file read/write) with small hand-built inputs. No pipeline or backtest on fake data.
Rules: hat_live written only by these data paths; never read or print .env; no backtests. Do not run the full update while the 5m import from builder backtest-infra is still running (logs /data/workspace/hat-data-isin/logs/infra-2026-10-28/import-chain.log, pid 3128370); wait for it, then do the first real run and report what each step did. One substantial PR. Address CodeAnt findings once.
Deliver: the PR, READY TO MERGE <full sha>; then after the first real run, a per-step table ending DAILY UPDATE LIVE.
